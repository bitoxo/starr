# Service capabilities

Verified facts about the APIs of the services Starr talks to: media servers, acquisition backends (Radarr, Sonarr, Lidarr, Whisparr) and metadata sources (TMDB, MusicBrainz/ListenBrainz, StashDB and others). Starr's adapters cite this file in their code comments, and an adapter may only build on a fact listed here with evidence. Found a fact that is wrong or outdated? Open an issue or a pull request with the evidence: a source or docs link, or a request and response from a running instance with personal data removed.

**Evidence marks**

- **[S]**: read in the service's source code or official docs (version or branch noted where known).
- **[V]**, **[V date, version]**: verified by experiment against a running instance: a disposable container for self-hosted services unless stated otherwise, the public API for hosted ones ("recorded" marks read-only requests whose responses are committed as fixtures). Dates are 2026, written month-day (`10-02` is 2 October).
- **[S+V]**: both.
- **[?]**: unverified or derived (from documented shapes, by analogy); verify before relying on it.
- **[design]**: Starr's own behaviour built on the facts around it, not a fact about the service.

Add new facts with evidence; never upgrade an unverified fact without an experiment. Research and experiments for the first facts ran from 2026-10-02 to 2026-10-31.

## Jellyfin

Versions: verified 10.11.11, 12.1.0, 12.2.0, 12.3.0 (12.0 and 12.4 only via release notes; 12.4 only updated .NET; on a real 12.4.0 server only the version string `12.4.0` was checked, no account writes [V 11-10]). Upgrade 12.1→12.2→12.3 kept accounts and API keys usable [V 10-12, 10-31].

**Auth.** API key (created via `POST /Auth/Keys`, needs elevation) gets role Administrator [S]. 12.x (`EnableLegacyAuthorization: false`) accepts only `Authorization: MediaBrowser Token=…` and `?ApiKey=`; `X-Emby-Token`, `X-MediaBrowser-Token`, `X-Emby-Authorization`, `Authorization: Emby …`, `?api_key=` → 401. 10.11 accepts all. Older third-party apps that only know legacy headers fail on 12.x unless the operator re-enables the option [V 10-02, 12.1.0/10.11.11; unchanged 12.2, 12.3].

**Users.** Create `POST /Users/New {Name, Password}`; without `Password` the account logs in with empty password. Set password `POST /Users/Password?userId=` with only `{NewPw}` (admin/API key needs no `CurrentPw`); old route `POST /Users/{id}/Password` still works. Non-admin can neither set a foreign password nor its own without `CurrentPw` (403). Disable `POST /Users/{id}/Policy` `IsDisabled:true` (login 403, existing token 401). Delete `DELETE /Users/{id}`. List `GET /Users` returns all incl. hidden (first admin is `IsHidden`) [V 10-02/10-03, 12.1.0].
- New accounts: `EnableAllFolders:true`, `IsDisabled:false`, `LoginAttemptsBeforeLockout:-1` [V]; in 12.3 also **`IsHidden:true`** (API-created users are not listed on the login screen) [V 11-02, recorded].
- Errors: unknown user ID on get/password/policy → **400** "Error processing request." (not 404) in 10.x; `GET /Users/{id}` answers **404** "User not found" in 12.3 [V 11-02, recorded]; duplicate name (also other case) → 400; concurrent create of same name → one account, second call 500; wrong/missing key → 401 empty [V 10-03, identical 12.2/12.3].
- Server identity: `GET /System/Info/Public` → `Id`, unauthenticated, stable [V]. During startup it answers before the setup wizard is ready (intermediate 503).
- Headless setup: `POST /Startup/Configuration`, `GET`+`POST /Startup/User`, `POST /Startup/RemoteAccess`, `POST /Startup/Complete`, then `POST /Auth/Keys?app=…` [V].

**Traps.**
- **Every password change logs out all devices** (`RevokeUserTokens`) [S+V]. Never re-set passwords periodically.
- **Policy is a full object**: partial policy → 400 (requires `AuthenticationProviderId`, `PasswordResetProviderId`). Read–modify–write; it changes only the set field. No ETag, so a service-side change between read and write is overwritten (ms window) [V].
- **Lockout uses the same flag**: with `LoginAttemptsBeforeLockout` set (0 means 3), failed logins set `IsDisabled=true`; an admin password change does not lift it, only `IsDisabled=false`. Default for API-created users is `-1` (no lockout). Logins on a disabled account return 403 and do not increment the counter. Service lockout is detectable as `IsDisabled` and counter ≥ limit. A naive reconcile of "active" would silently lift a security lockout [V 10-02/10-03, 12.1.0]. In 10.11.11 lockout did not trigger even with explicit 3 (probable bug, not investigated).
- `InvalidLoginAttemptCount` is taken from the written policy: reset it when disabling so a previously locked account doesn't look locked later [V].
- **Empty passwords accepted**: `{NewPw:""}` and `{ResetPassword:true}` → 204, login with empty password works. Starr must prevent empty passwords [V].
- Password rules: none beyond "admin not empty"; Unicode/emoji, quotes, backslash, `%20`, 1 and 300 chars work; edges not trimmed [V].
- Usernames: regex `^(?!\s)[\w\ \-'._@+]+(?<!\s)$`, not `.`/`..`. Accepted: spaces inside, umlauts, `@`, `'`, CJK, digits. Rejected: edge spaces, `/`, `;`, `<b>`, case duplicates. `.` rejected in 12.1, accepted in 10.11. Login case-insensitive. Since 12.0 names can change case and must be unique when normalized (case-only duplicates block the upgrade) [S+V].
- Login cost: PBKDF2-SHA512, 210,000 rounds, also for disabled accounts (0.3–0.9 s per login on CI) [S].

**Libraries.** `GET /Library/VirtualFolders` → `Name`, `ItemId` (32 hex). Create `POST /Library/VirtualFolders?name=&collectionType=&paths=` (comma list); name is sanitized and silently renamed on collision ("Filme2") — compare trimmed names. `collectionType`: `movies`, `tvshows`, `music`, `musicvideos`, `homevideos`, `boxsets`, `books`, `mixed` — no podcasts [S+V].
- `EnableAllFolders:false` + `EnabledFolders:[id]` → only that library; later libraries not visible. `EnableAllFolders:true` → later libraries visible immediately. `[]` → nothing [V].
- Unknown or duplicate IDs in `EnabledFolders` accepted silently (204) — validate before writing [V].
- **Renaming a library gives it a new `ItemId`** after rescan; accounts keep the old ID and still see it under the old name. Library IDs are not durable [V].

**Inventory via provider IDs.** `GET /Items?userId=…&recursive=true&includeItemTypes=Movie,Series&fields=ProviderIds` → `{"Imdb":…,"Tmdb":…,"Tvdb":…}`. With API key but without `userId` the list was empty. Series provider IDs appear only after metadata fetch (empty right after scan). Seasons `/Shows/{id}/Seasons`, episodes `/Shows/{id}/Episodes` (`ParentIndexNumber`/`IndexNumber`, missing ones `LocationType: Virtual`). No filter by a specific provider ID (only `hasTmdbId`/`hasTvdbId`) — list and compare [V 10-10, 12.1.0].

**Probe and product.** `GET /System/Info` needs authentication (policy `FirstTimeSetupOrIgnoreParentalControl`; an API key passes) and returns `Version`, `Id` (server ID) and `ProductName`; `/System/Info/Public` is anonymous and proves no key [S master `Jellyfin.Api/Controllers/SystemController.cs`]. `ProductName` is the assembly product `Jellyfin Server` (`[assembly: AssemblyProduct("Jellyfin Server")]` in `Jellyfin.Server/Properties/AssemblyInfo.cs`, set from `ApplicationHost.Name`) [S]. Emby's `SystemInfo` has no `ProductName` (see Emby) — Starr's Jellyfin adapter requires it, the Emby adapter refuses it.

**Item queries (Starr's use).** `GET /Items?UserId=&ParentId=<library ItemId>&Recursive=true&IncludeItemTypes=Movie,Series&Fields=ProviderIds&SortBy=DateCreated,SortName&StartIndex=&Limit=&EnableTotalRecordCount=true` → `{Items, TotalRecordCount, StartIndex}`; `enableTotalRecordCount` defaults to true; `Users/{userId}/Items` is `[Obsolete("Kept for backwards compatibility")]`; with an API key and no `userId` the controller runs without a user [S master `ItemsController.cs`], which matched the empty list seen in the experiment above. Starr queries through an enabled administrator with `EnableAllFolders` (from `GET /Users`), so a listing can be complete; without one the sync fails with `rejected`. Episodes: `IncludeItemTypes=Episode&IsMissing=false`, counted per `SeriesId` × `ParentIndexNumber` as distinct `IndexNumber…IndexNumberEnd`, skipping `LocationType: Virtual` [S]. Query parameter names bind case-insensitively (ASP.NET Core) [S]. Paging is by offset: completeness = total present, unchanged across pages, and exactly that many distinct IDs received; one removal plus one addition between two pages cannot be detected (count still matches) — the inventory's two-complete-runs rule covers it [S, design].
- Account fixtures `crates/adapters/jellyfin/fixtures/12.3.0/accounts/` are **recorded** from a disposable `jellyfin/jellyfin:12.3` container (2026-11-02: users, policies, lockout after 3 failed logins with `LoginAttemptsBeforeLockout: 3` → `IsDisabled: true`, counter 4).
- Account writes are tested against a stateful fake (`starr-adapter-kit` `contract::media_server`) seeded from these recorded reads; its write behaviour (204 on policy and password, 400 on a partial policy or a taken name, password taken at create) follows the facts above, the write **responses are not recorded** [?]. `HasPassword` after a password write is read back but not relied on (only an explicit `false` fails) until verified. The same holds for Emby. Because a failed read-back would otherwise retry the write (and sign the devices out again), `accounts.password` tries each password write at most once per handoff unless the service itself was in trouble (unreachable, throttled, key refused) [design; verify `HasPassword` against a disposable container before relying on it].
- Contract fixtures `crates/adapters/jellyfin/fixtures/{10.10.7,10.11.11,12.3.0,12.4.0}` are built from the source DTO shapes (`SystemInfo`, `UserDto`, `VirtualFolderInfo`, `BaseItemDto`), **not recorded** [?] — record them from a live instance.

**"Open in" links.** jellyfin-web's router builds item links as `#/details?id=<id>&serverId=<serverId>` (`src/components/router/appRouter.js`), served under `/web/`, so Starr links to `<public URL>/web/#/details?id=…&serverId=…`. The item details controller falls back to the current server when `serverId` is missing (`params.serverId ? ServerConnections.getApiClient(params.serverId) : ServerConnections.currentApiClient()`, `src/apps/legacy/controllers/itemDetails/index.js`) [S jellyfin-web master 2026-11]. Not clicked through on a live instance yet [?].

**Webhooks.** Official plugin only; event list (item added, user created) [?]. 12.0 release notes: remove repository plugins before upgrading.

## Emby

Closed source; REST reference is unversioned. Verified against 4.10.1.0 (accounts) and 4.10.0.40 (libraries/inventory).

**Auth.** API key via `X-Emby-Token` or `?api_key=`, with or without `/emby` prefix. Key created with `POST /Auth/Keys?App=…` serves user create, policy, password and delete [V 10-02]. Rights of an API key are not documented by Emby [S]; in 4.10.1.0 an API key created via `POST /Auth/Keys` lists users (including hidden and disabled ones), creates users, sets passwords and writes user policies [V 11-02, recorded]. 4.9 not checked. Admin login: `POST /Users/AuthenticateByName {Username, Pw}` with `X-Emby-Authorization: Emby Client=…, Device=…, DeviceId=…, Version=…` [V].

**Users.** `POST /Users/New`, `GET /Users` (= `/Users/Query`, includes hidden; first admin not hidden), `GET /Users/{Id}`, `POST /Users/{Id}/Policy`, `POST /Users/{Id}/Password {NewPw}`, `DELETE /Users/{Id}` or `POST /Users/{Id}/Delete` [V].
- **Create ignores `Password`**: account is created active with empty password. Neither `Policy.IsDisabled` nor `CopyFromUserId` creates it disabled. Safe order: create → disable → set password → enable. If create times out but succeeded, an active passwordless account remains [V 10-03]. Starr: when a step after a successful create fails, the adapter retries the disable and, if that fails too, writes a random password nobody knows (other route), reports the account as unfinished, and Starr owns it with "no password written": the planner disables it and never enables it before the member's password is written; it shows under "needs you" [design, fake only]. A create that times out without a response is not covered: the account appears in the next scan as a name-taken conflict [?].
- **Concurrent creates produce duplicate accounts** (2 of 5 rounds, also case variants). Otherwise duplicate names (any case) → 400 "already exists". With duplicates Emby always logs in the **oldest** account (`DateCreated`, 7 decimals, sortable as text). Rule: oldest wins; Starr's younger duplicate stays disabled with random password and is reported as conflict [V].
- Errors: unknown user on get/password → 404; on policy → **500** "Object reference not set…"; non-Guid ID → 500 "Unrecognized Guid format"; wrong key 401 "Access token is invalid or expired."; wrong password 401, disabled 403 "…disabled…", locked 403 "…temporarily locked out…" [V].
- Headless setup: `POST /emby/Startup/Configuration`, `GET`+`POST /Startup/User`, `/Startup/RemoteAccess`, `/Startup/Complete` [V]. Server identity `GET /System/Info/Public` → `Id` [V].

**Traps.**
- **Non-admin token on `POST /Users/{otherId}/Password` ignores the path ID and changes the caller's own password** (204, no `CurrentPw`). Only call with API key/admin token, and verify every change by login, not by status code. Users can change their own password without the old one → drift via apps is possible [V].
- **Partial policy is accepted (204) and resets all other fields to defaults** (e.g. `EnableAllFolders` back to true, library grants gone). Always read–modify–write [V].
- Every admin password change revokes the user's tokens (logs out all devices) [V].
- **Lockout differs from Jellyfin**: 10th failed attempt sets `LockedOutDate`, `IsDisabled` stays false; even the right password then gets 403 for ~60 s, then expires by itself. Admin password change doesn't lift it; `Policy.LockedOutDate=0` does. Failed attempts on a disabled account also count. After lockout the counter resets to 0 and `LockedOutDate` stays set even after expiry and successful login — current lock state is not readable from the policy. No threshold setting found. Does not collide with reconciling "active" [V].
- Empty password: new users have none; `{NewPw:""}` and `{ResetPassword:true}` set empty. The forum workaround "ResetPassword first" is not needed in 4.10.1.0 [V].
- Password rules: none. Usernames accepted: spaces, umlauts, `@`, `'`, `/`, CJK, `;`, `.`; edge spaces silently trimmed; rejected `<b>` (error message claims a stricter rule than enforced), empty, case duplicates. Login case-insensitive [V].
- Emby Connect accounts: passwords managed by emby.media, changeable only by the person [S].

**Libraries.** `POST /Library/VirtualFolders?Name=&CollectionType=&RefreshLibrary=false&Paths=` (204). `GET /Library/VirtualFolders` → `Guid` and numeric `ItemId`; `EnabledFolders` takes the **Guid**. Unknown Guids and numeric IDs are stored silently [V]. Deleting a library returned 500 (not pursued). Starr keeps both per library (`MediaLibrary.id` = `ItemId` for item queries and inventory, `grant_id` = `Guid` for grants; a folder without `Guid` stays in the inventory but cannot be mapped or granted, never with the `ItemId` instead).
**Inventory.** Libraries created with `LibraryOptions: {}` have no metadata fetchers and return **no ProviderIds**. Use `GET /Libraries/AvailableOptions?LibraryContentType=…&IsNewLibrary=true` defaults when creating; then `Tmdb`/`Tvdb` appear after refresh. Emby writes `IMDB` (series/episode) vs `Imdb` (movie) — compare provider keys case-insensitively [V 10-10, 4.10.0.40].
**Probe and product.** `GET /System/Info` ("Requires authentication as user") returns `SystemInfo` with `Version`, `Id`, `ServerName` and **no `ProductName`** [S Emby REST reference `SystemService/getSystemInfo`]. A `ProductName` therefore means Jellyfin; the Emby adapter refuses it. Tested range in Starr: `>=4.10, <4.11` (only 4.10 verified).
**Item queries (Starr's use).** `GET /Users/{adminId}/Items?ParentId=<library ItemId>&Recursive=true&IncludeItemTypes=Movie,Series&Fields=ProviderIds&StartIndex=&Limit=` → `{Items, TotalRecordCount}`; library `ParentId` is the numeric `ItemId` from `VirtualFolders`, not the `Guid` [S REST reference; numeric IDs per the experiment above]. `GET /Users` may answer an array or a `/Users/Query`-style `{Items, TotalRecordCount}`; Starr accepts both. Whether `/Items` without a user works with an API key is unverified [?]. Same completeness rule and episode counting as Jellyfin.
- Contract fixtures `crates/adapters/emby/fixtures/{4.9.1.90,4.10.0.40,4.10.1.0}` are built from the REST reference shapes, **not recorded** [?]; the account fixtures in `4.10.1.0/accounts/` are **recorded** from a disposable `emby/embyserver:4.10.1.0` container (2026-11-02). User IDs there are 32-hex strings; `GET /Users` with an API key answers a plain array; `LockedOutDate` is the lock's start time in Unix milliseconds.
- Account writes run against the same stateful fake as Jellyfin's, here resetting every policy field a partial write leaves out (the trap above), and creating twins when duplicates are allowed; write responses are not recorded [?].
**"Open in" links.** Emby web item pages are `<host>/web/index.html#!/item?id=<id>&serverId=<serverId>` (also `app.emby.media/#!/item?id=…&serverId=…`) [S community: emby.media topics 115187 (2023-01) and 134524 (2025-08); no official doc found]. A forum reply says `serverId` is not needed; one report says the parameter is case-sensitive (`serverId`). Not verified on a live instance [?].
**Webhooks.** Native since 4.8.0.80 without Premiere [S]; exact event list [?].

## Navidrome

Version 0.64.2. Native API is not documented as stable [?]. 0.64.0 re-encoded internal IDs (observed in production by an earlier Navidrome client).

**Auth.** No admin API key. `POST /auth/login` with admin user/password → JWT, sent as `X-ND-Authorization: Bearer …`. JWT lifetime 48 h; every native API response returns a renewed token in `X-ND-Authorization` (sliding). Strategy: reuse token from response header, re-login on 401 [V 10-02]. First admin: `POST /auth/createAdmin` (second call 403).
- **Login rate limit: 5 requests per 20 s per client IP**, successful logins count, applies to all users behind that IP; the window weights the previous one (429 already on the 4th attempt after 21 s pause). Reuse the admin JWT [V].
- Subsonic API cannot manage users (`createUser` etc. → 501) [S]. Subsonic auth: `u`+`p`, `u`+`t`+`s` (md5(password+salt)), or OpenSubsonic `apiKey`. Token auth requires the plaintext, so Navidrome stores passwords reversibly encrypted (default key constant "just for obfuscation") [S].
- **Subsonic throttle**: after 5 failed attempts per IP+username, `/rest/*` answers error 40 even for the correct password until the window expires — a client with a stale password can block a correct client on the same connection [V].
- Version without credentials in URL: `POST /rest/ping` with form body → `serverVersion`; `/app/` page also contains it [V]. No server identity (no `Id`) found [V].
- **Recorded 2026-11-06** by read-only requests (`GET`s and one admin login) against a live Navidrome 0.64.2 with one library: `crates/adapters/navidrome/fixtures/0.64.2/recorded/` (sanitised, README there), marked [V 11-06, recorded] below.

**Users.** `POST /api/user {userName, name, password, isAdmin}` → `{id}`; `PUT /api/user/{id}` with the **full** user object plus `password`, no `currentPassword` → 200; old JWT of the user invalid afterwards (password change bumps `TokenEpoch`). `DELETE /api/user/{id}`. `GET /api/user` without paging returns all (`X-Total-Count` = length) [V].
- **Partial PUT `{password}` returns 200 but empties `userName` and `name`** (and resets `createdAt`); the account can't log in until a full PUT repairs it [V].
- **No disable flag** — rollback means delete or random password [S].
- **No server-side name or password rules**: accepts edge spaces, `/`, CJK, even an **empty `userName`**; only case duplicates rejected (400 `ra.validation.unique`). User without `password` logs in with empty password via native API (not Subsonic). Login case-insensitive [V].
- **Concurrent creates make twins** (uniqueness checked only in app code) [V].
- Errors: unknown user `GET` → 404, `PUT` → 400 `ra.validation.unique`, `PUT …/library` → 404 [V].
- **Only admin may delete itself** → no admin left, `createAdmin` stays locked. Never include Starr's own admin account in rollback [V].
- Special-character passwords work with native API and all three Subsonic methods; behaviour of individual Subsonic clients [?].

**Libraries.** `GET /api/library` → numeric `id`, `name`; rename keeps ID. Create `POST /api/library {name, path}` (path must exist in the service's filesystem [S, observed by an earlier Navidrome client]). `PUT /api/user/{id}/library {"libraryIds":[…]}` (admin only). New non-admins get only the default library; **no "all libraries" right** — new libraries are not granted automatically. Empty list → 400 for non-admins; unknown or duplicate IDs → 400, nothing changed. Admins always have all libraries; assigning to them is rejected [V]. No download right or age rating per user [S].
**Starr's account writes.** Read: `GET /api/user` (complete only with `X-Total-Count` = length, no repeated ID, every user with ID and name), `GET /api/user/{id}`, `GET /api/user/{id}/library` only where a user object lacks `libraries` [?]. Writes, each after reading the user and refusing an admin: full-object `PUT /api/user/{id}` + `password` (member password, or a random one to disable/lock), `PUT /api/user/{id}/library {libraryIds}` (only listed IDs, never empty), `POST /api/user {userName, name, password: <random>, isAdmin: false}` (serialized; twins: oldest `createdAt` wins), `DELETE /api/user/{id}` (due deletion order only). Write shapes are from source; the fixtures in `crates/adapters/navidrome/fixtures/0.64.2/derived/` (`users.json` added) are hand-written and stay for the write tests [?]. Reads [V 11-06, recorded]: `GET /api/user` answers every user with `X-Total-Count` = length, each user object carries `libraries` (full library objects), `GET /api/user/{id}` the same object and `GET /api/user/{id}/library` the user's libraries; `email` may be empty, `lastLoginAt`/`lastAccessAt` may be `null`. Login reply `{id, isAdmin, name, subsonicSalt, subsonicToken, token, username}` (no `lastFMApiKey`/`avatar`); the login answer carries `X-Ratelimit-Limit: 5`. Every native API answer renews `X-ND-Authorization`.
**Albums (Starr's inventory).** `GET /api/album?_start=&_end=&_sort=id&_order=ASC&library_id=<id>` (react-admin paging, total in `X-Total-Count`); album JSON (`model/album.go`): `id`, `libraryId`, `name`, `albumArtist`, `maxYear`, `songCount`, `mbzAlbumId`, `mbzAlbumArtistId`, `mbzReleaseGroupId` (omitted when empty), `missing` (every file gone; the album stays until a purge) [S master `model/album.go`]. `library_id` is a REST filter of `persistence/album_repository.go`, `Count` and `ReadAll` apply the same options (so the total follows the filter); there is no default filter for `missing` [S]. Starr pages by what arrived, treats a listing as complete only when every page reported the same total and that many distinct IDs arrived, counts missing albums but does not list them, and marks the listing incomplete when an album of another library shows up (a Navidrome without the filter). Version without credentials: `GET /rest/ping?v=1.16.1&c=starr&f=json` answers HTTP 200 with a Subsonic error envelope (`status: "failed"`, error 10 "missing parameter: 'u'") that still carries `type: "navidrome"` and `serverVersion` (`0.64.2 (<commit>)`) [V 11-06, recorded]. Login reply `{token, isAdmin, …}` (`server/auth.go`) [S; V 11-06, recorded]. "Open in": `<public url>/app/#/album/<id>/show` [S].
- Albums [V 11-06, recorded]: the album page shape is as read in source plus image fields (`imageHash`, `thumbHash`, `dominantColor`, `imageWidth`, `imageHeight`), `genres`, `tags`, `participants`, `discs`, ReplayGain; `X-Total-Count` is the total of the filter (the same with `library_id=1` and without a filter, because the instance has one library; `library_id=999` answers `[]` with `X-Total-Count: 0`), so the total does follow `library_id`. **None of the library's albums (several thousand) has an `mbzAlbumId`, `mbzReleaseGroupId` or `mbzAlbumArtistId` key**, and the Subsonic `musicBrainzId` is empty on all of them: the recorded library's files carry no MusicBrainz tags. Absent keys are omitted, not empty strings; the adapter reads them as "no MBID" (`recorded.rs`).
- **Accepted limitation (decided 2026-11-06):** albums already in a music library without release-group MBID tags are not recognised as available: they look requestable, and a request for one ends under "Needs you" after the download (Starr matches albums by release-group MBID only; no retagging, no fallback to Lidarr's `hasFile`). New Lidarr downloads are tagged when Lidarr's audio tagging is not "No" (e.g. "For new downloads only") [?].
- The derived fixtures in `crates/adapters/navidrome/fixtures/0.64.2/derived/` stay for what the recording cannot show: albums with MBID tags, a second library, albums whose files are all missing, and every write.
- Open: `mbz_release_group_id` from a real scan of tagged (Lidarr-imported) files; the album deep link clicked through [?].
**Events.** None; plugin system exists, outbound events [?].

## Audiobookshelf

Version 2.37.1 (podcasts also 2.37.2).

**Auth.** `POST /api/api-keys {name, userId, isActive:true}`; without `isActive` the key is inactive (401). Key is a JWT acting as the given user (must be an admin/root user that sees all libraries — `GET /api/libraries` shows only that user's libraries). Sent as `Authorization: Bearer` or `?token=`. **The key is only visible in the create response**; re-setup renews it. Validate a known key with `GET /api/me` [V]. Login `/login` returns access token (1 h), legacy token (no `exp`), and with `x-return-tokens: true` a refresh token (30 days) [V]. Headless init: `POST /init {"newRoot":{…}}` [V]. No server identity in `/status` [V].
- **Login rate limit: 40 per 10 min per IP** (`RateLimit-Policy: 40;w=600`), successful logins count; API-key requests unaffected. Behind a proxy without correct client IP all members share it [V].

**Users.** `POST /api/users` (`username`, `password` non-empty), `GET /api/users` (all, unpaged), `PATCH /api/users/:id`, `DELETE /api/users/:id`. Admin may not change root; nobody deletes themselves [S+V].
- **`isActive` defaults to false** on create → login 401 [V].
- Default permissions: `download`, `accessAllLibraries`, `accessAllTags` true, `accessExplicitContent` false (admin type: true). Permissions sent on create are applied; PATCH `permissions` merges per field [V].
- Password via `PATCH {password}` works; **`{password:""}` is silently ignored** (old password stays) [V].
- **Password change revokes only refresh tokens**; existing access token (≤1 h) and legacy token (unlimited) stay valid. To end sessions set `isActive:false`, which revokes all immediately [V].
- **Usernames case-sensitive on create, case-insensitive on login**: `ALICE` can be created next to `alice` but cannot log in with its own password. Starr must enforce case-insensitive uniqueness. Edge spaces kept as part of name [V].

**Libraries.** `GET /api/libraries` → UUID `id`; rename keeps ID. `accessAllLibraries:false` + `librariesAccessible:[id]` → only those; `true` → new libraries visible [V].
- PATCH applies `librariesAccessible` **only inside a `permissions` object**; otherwise 200 and nothing changes [V].
- Unknown IDs accepted silently; deleted libraries stay in the list; duplicates stored twice [V].
- `accessAllLibraries:false` with empty list: listing shows **all** libraries, none can be opened. Never write an empty list with `false` [V].
- A non-empty `librariesAccessible` filters the overview even with `accessAllLibraries:true`; clear it when switching to "all" [V].

**Podcasts.** Search `GET /api/search/podcast?term=&country=` uses iTunes Search; result `id` is the iTunes ID [S+V]. Create `POST /api/podcasts` (admin only) requires `media.metadata`, `libraryId`, `folderId`, `path` inside the library folder and not yet existing; working body `{libraryId, folderId, path, media:{metadata:{title, feedUrl, itunesId, imageUrl}, autoDownloadEpisodes:false}}`. Without `imageUrl` no cover; a failed cover download is not reported [V 10-31].
- **Subscriptions are library-wide**, no per-user subscription (only progress/playlists per user) [S].
- Auto-download fields `autoDownloadEpisodes`, `autoDownloadSchedule` (default cron `0 * * * *`), `maxEpisodesToKeep` 0, `maxNewEpisodesToDownload` 3; set via `PATCH /api/items/:id/media` (needs `canUpdate`). After 24 failed feed checks ABS disables auto-download itself [S+V].
- A **new subscription without episodes downloads nothing existing**: auto-download only fetches episodes newer than the newest present one (or `lastEpisodeCheck`, set at create). `lastEpisodeCheck` can be patched to steer this [V].
- `maxEpisodesToKeep` deletes oldest episodes with files and **all users' listening progress** [S].
- `POST /api/podcasts/:id/download-episodes` does **not** dedupe against existing episodes (same GUID twice → two files). Check GUID **or** enclosure URL yourself before downloading [V].
- `POST /api/podcasts/feed {rssFeed}` parses a feed (metadata incl. image URL, episodes with `guid`, `enclosure.url`, `publishedAt`) [V].
**Events.** Apprise notifications (`onPodcastEpisodeDownloaded`, `onRSSFeedFailed`, …) [S]; Apprise JSON webhook target [?]; socket events like `user_added` [S].

Paths are `/` + 31–32 alphanumerics + `.jpg`/`.png`. **The CDN resolves `..` in paths** (also `%2e%2e`) — validate paths in Starr's proxy [V 10-12].
- Data changes constantly; tests against the live API can fail without code change [V].
- **Auth (Starr adapter `tmdb`)**: the v4 "API Read Access Token" (a JWT, a few hundred characters) sent as `Authorization: Bearer …` is accepted by every v3 endpoint Starr uses [V 11-01, 25 requests]. The 32-hex v3 "API key" works only as the `api_key` query parameter [S]; Starr accepts only the read token (no credentials in URLs) and refuses a 32-hex value for TMDB services with `validation.tmdb_read_token`, and a base URL with a path (`…/3`) with `validation.tmdb_base_url`.
- **Probe**: `GET /3/authentication` validates the token and nothing else; the body is just `{"success":true}` with `cache-control: private, max-age=0`; a wrong token → 401 `{"status_code":7,…}` (that error carries `public, max-age=300`) [V 11-01]. Not cached by Starr. The adapter reports version `3.0.0.0` (path version; tested range `>=3, <4`). Because TMDB reports no version, the shared probe contract suite (which needs an out-of-range version fixture) does not apply; `tests/contract.rs` covers the same cases for TMDB.
- **Adapter choices** (Starr; thresholds not yet measured against real data): Upcoming movies with a release region = `region` + `with_release_type=2|3` + `release_date.gte=today` + `primary_release_date.gte=today−365d` (drops re-releases); without region `primary_release_date.gte=today`. Upcoming series = `first_air_date.gte=today` (no regional TV dates). On your services = `watch_region` + `with_watch_providers` (OR) + `with_watch_monetization_types=flatrate|free|ads`, movies released within 365 days, series with an episode aired within 90 days; no providers → empty list without a request. Top rated = `vote_average.desc` with `vote_count.gte` 5000/1000. `without_genres` is sent comma-separated; whether `,` or `|` means "any" for exclusion is **[?]**, so Starr filters results by `genre_ids` again (and by original language, the only filter for Trending). Trending page N drops ids seen on the three pages before it (bounded lookback, usually cached). Search uses `/3/search/multi` and drops `media_type: person`. Language `de-CH` is sent as `de-DE`; empty title/overview triggers an `en-US` fetch of the same request; videos use `include_video_language=<lang>,en,null`.
- **Caching in Starr**: responses stored per instance and request (path + query, never the token) in `catalog_cache` for `max-age − Age`, at least 5 min, at most 183 days; housekeeping deletes expired rows and caps the table at 20,000 rows. Image proxy sizes are an allowlist equal to the union of `/3/configuration` sizes (`w45 w92 w154 w185 w300 w342 w500 w780 w1280 h632 original`); file names must match `^[A-Za-z0-9]{20,40}\.(jpg|png)$`. Images are cached on disk (`<data_dir>/cache/images`, 1 GiB, LRU by mtime).
- **Contract fixtures**: `crates/adapters/tmdb/fixtures/v3/recorded/` are **recorded from the live API on 2026-11-01** (`record-fixtures.sh`, token read from a file at runtime, bodies only) and exercised by `tests/recorded.rs`. Observed then [V 11-01]: trending movie pages 1 and 2 shared one id (repeats across pages confirmed); page 501 → 400 `status_code 22` while `total_pages` was 1001; 187 languages, 251 countries, 139 provider regions, 84 movie providers in CH (Netflix first by `display_priorities.CH`); `de-CH` for Squid Game returned the Hangul title and an empty overview while `de-DE` was translated; image paths were `/` + 26–27 alphanumerics + `.jpg`/`.png`; `max-age` was 134–497 s for trending, ~1–7 h for discover, search, details and reference data. The fixtures directly under `fixtures/v3/` are **synthetic scenarios** (duplicates within a page, empty overviews, odd values, errors) built from these shapes for `tests/contract.rs`.

## Cross-service conclusions

1. **Provisioning chain works for all four consumer services**: admin creates a local account and sets a password without the old one — Jellyfin (API key), Emby (API key), Navidrome (admin login only), Audiobookshelf (admin-bound API key) [V].
2. **Starr needs the plaintext password at set time**: every endpoint takes plaintext and hashes itself; no hash import. Options: write-only (hold in memory during change/login, "password pending" for later services) or reversible encryption. Starr writes on entry: it stores only the member's password hash and, whenever the member types the password, hands the plaintext sealed to the worker as a one-time password handoff (deleted once written, at the latest after an hour); no recoverable password stays at rest.
3. **Passwords are not reconcilable**: the only check is a real login, which has side effects (lockouts, rate limits); re-setting logs out devices (Jellyfin, Emby, Navidrome JWT; ABS refresh only). Write only on change, track a per-account password generation.
4. **Lockout vs. reconcile**: Jellyfin locks via `IsDisabled` (collides with "active" state; treat service lockout as its own state, not drift); Emby via `LockedOutDate` (no collision). Partial updates reset fields in Emby policies and Navidrome users — read–modify–write everywhere.
5. **Password policy**: only Seerr enforces ≥ 8 (password endpoint only); Jellyfin, Emby, Navidrome accept empty passwords. A Unicode/emoji/quote/backslash/`%20`/`+`/space test password worked in all verified services; edges never trimmed. Third-party app behaviour (Subsonic `p=`, tvOS keyboards) [?].
6. **Username rule**: Jellyfin is strictest (`[\w '._@+-]`, no edge spaces). Navidrome and ABS check only uniqueness (ABS case-sensitive on create, insensitive on login). All log in case-insensitively; Komga, Immich, Seerr log in by email. Recommendation: lowercase `[a-z0-9._-]`, case-insensitive unique, plus required email; map by remote ID, not name (Jellyfin 12 names are mutable).
7. **Admin credentials**: API key suffices for Jellyfin, Emby, ABS, Seerr, *arr, Stash, Immich; **Navidrome requires an admin password**. Protect Starr's own admin accounts in every service from rollback.
8. **Rollback**: disable exists in Jellyfin, Emby (`IsDisabled`) and ABS (`isActive`), and ends existing tokens immediately; Navidrome and Seerr have no flag (random password / remove rights). Delete verified via contract suite for ABS, Emby, Jellyfin, Navidrome (second delete → not found). Deleting destroys watch state, favourites, playlists [unverified per service] — two stages: suspend, then delete after a grace period with preview.
9. **Concurrent creates**: Emby and Navidrome create duplicates/twins; Jellyfin yields one plus a 500; Seerr may lose an account and reuse its ID. Serialize creates per service and verify by reading back.
